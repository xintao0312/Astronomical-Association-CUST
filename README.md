# CUST 理工天文 · 社团网站

一个纯静态的社团主页 —— **零运行时依赖**，不需要 Node、不需要打包、不需要联网字体。
直接用浏览器打开 `index.html` 就能看。

```
index.html          首页（hero / 社团概况 / 关于 / 活动预览 / 加入 / 联系方式）
about.html          关于我们（来历 / 三个小组 / 协会概况 / 常见问题）
activities.html     社团活动（四条常规线完整，其余小节为占位符，见下）
gallery.html        星空画廊（13 张作品 + 灯箱 + 拍摄方法）
404.html            错误页

assets/
  css/base.css      设计令牌（亮暗两套颜色）、重置样式、通用排版、占位符样式
  css/main.css      组件与布局：导航、hero、卡片、画廊、时间线、表格、页脚、灯箱
  js/main.js        主题切换、吸顶导航、滚动进度、星空生成、滚动揭示、灯箱
  icons.svg         25 个内联图标的唯一来源（界面小图标，不含社徽）
  img/              由 image/ 生成的图片资源：
                      milkyway-* / group-observation-*  活动照片，多尺寸 JPEG + WebP
                      aac-badge-*                       社徽，用于导航栏与页脚
                      aac-hero-* / aac-hero-dark-*      hero 社徽背景，亮/暗各一份
                      favicon.png                       站点图标（取自社徽）

image/              原始素材（未改动，保留作为归档）
tools/              构建与校验脚本（可选，网站本身不依赖它们）
```

## activities.html 的两种内容状态

这一页刻意分成两段：

* **常规项目 —— 内容完整。** 四条常年运行的线（路边天文夜、深空摄影工坊、天文讲堂、
  星空观测营）保留全部正文与场次信息，是这一页真正的正文。
* **其余小节 —— 只有版式，没有文字。** 页面导语、排期表、观测记录表、全年节奏、
  底部 CTA 的说明文字全部替换为 `［…］` 占位符，但**表格列头、行数、时间线节点、
  卡片与图片的排版完全保留**，社团照着填即可。

表格占位符按列名生成，因此列头与单元格内容一一对应（例如列头「天空条件」对应单元格
`［天空条件］`）。行数是 `tools/pages/activities.mjs` 顶部的两个常量：

```js
const SCHEDULE_ROWS = 8;   // 排期表行数
const LOG_ROWS = 4;        // 观测记录表行数
```

改这两个数字即可增减行数。直接编辑生成后的 `activities.html` 同样有效。

## 图片信息也是占位符

除了 hero 那片装饰性背景（社徽，见下节，纯装饰、不承载信息，也不出现在图片说明的位置），
站内**所有**图片说明都已改为占位符，版式（尺寸、裁切比例、说明条、灯箱）完全保留：

| 位置 | 占位内容 |
|---|---|
| 首页「最近的活动」三张卡片 | 图片上的说明条 → `［图片说明］` |
| 首页「关于我们」合影 | 说明条 → `［图片说明］` |
| 活动页配图 | 说明条 → `［图片说明］` |
| 画廊四张作品 | 说明条标题、灯箱标题、灯箱描述 → `［图片标题］` 等 |

填写时改一处即可：画廊的 `title / desc / alt` 三个字段都在
`tools/pages/gallery.mjs` 顶部的 `SHOTS` 数组里，灯箱会自动读取（灯箱不是把文字写死在
HTML 里，而是运行时从卡片的 `data-title` / `data-desc` 取），不用改两遍。

两点说明：

* **说明条改为常显。** 原本标题只在鼠标悬停时出现，但悬停态在触摸设备上根本触发不了，
  占位符也就看不见了。现在说明条始终显示，稳定落在图片下缘的渐变蒙版上，两种主题下
  对比度都足够。
* **`alt` 文本没有留空。** 按无障碍规范，纯装饰图片应写 `alt=""` 让读屏器跳过；
  但这四张是作品本身，属于内容，所以保留了非空 `alt` 占位符，替换时请填真实描述 ——
  这是唯一一处不建议长期保留占位符的地方。

## 画廊的版式

四张照片排成**两列并列的 2×2 方格**，每格尺寸完全一致。

难点在于四张图的原生比例差得很远（三张横构图约 3:2，合影接近 1:1.5 竖幅），
统一尺寸必然要裁切。选比例时用真实图片实测了各方案的裁切损失：

| 统一比例 | 三张横图保留 | 合影保留 |
|---|---|---|
| 3:2 | 89%—90% | 74% |
| **4:3** | **99%—100%** | **89%** |
| 5:4 | 93% | 83% |
| 1:1 | 74%—75% | 67% |

最后选 **4:3** —— 它几乎不损失横构图，对唯一的竖幅也最宽容。

**改比例只改一个值。** `assets/css/main.css` 里 `.gallery-grid { --shot-ratio: 4 / 3 }`
控制全部四格，不用逐张调。**裁切保留哪一部分**则由每张照片自己的 `object-position`
决定（写在 `tools/pages/gallery.mjs` 的 `SHOTS` 里）：合影设成 `center 30%` 偏上，
保证十几个人脸不被切掉；星空图居中。

窄屏（≤860px）自动降级为**单列通栏**，比例不变，四张照片依次铺开。

## 亮色与暗色

两套主题由 `assets/css/base.css` 顶部的一组自定义属性驱动，页面上的颜色**全部**
取自这些变量，因此不可能出现某个组件只适配了一种模式的情况。

| | 亮色模式 | 暗色模式 |
|---|---|---|
| 页面底色 | 蔚蓝 → 长春花 → 近白 | 深蓝 → 靛紫 → 近黑 |
| 色相走向 | 214° → 232° | 214° → 232° → 268° |
| 主色 | `#1d63d8` | `#74a4ff` |
| 蓝紫重点 | 渐变文字与品牌按钮 | 同样位置、同样走向 |

关键约定：

* **站点标识用真实社徽。** 导航栏与页脚的标识取自 `image/aaclogo1.png`（圆形徽标，
  透明底），放在原有的品牌渐变方砖上；暗色模式对它做 `filter: invert(1) hue-rotate(180deg)`，
  一张图适配两套主题，不必再出一份反色文件。
* **色相锚点只有一处。** `--h-brand` / `--h-mid` / `--h-violet` 在 `:root` 里定义
  一次，两套主题各自引用，所以色相永远不会各自漂移。
* **每个上色令牌都有暗色对应项。** 38 个需要配对的令牌逐一检查，不存在只定义了一半的。
* **同一份社徽、同一处构图。** hero 与子页面页头用的是同一份社徽（`image/aaclogo3.png`，
  横版组合），位置由 `--hero-focus` 统一控制，两处共用。
* **社徽按主题出两份配色。** `aaclogo3.png` 是「白底 + 深蓝图案」的不透明图，
  所以暗色模式用的是**亮度反转**版本（图案变亮、白底变近黑），配合
  `mix-blend-mode: screen`：黑底不贡献任何像素，只有图案本身把背景点亮。
  反转会让蓝色变成它的补色（琥珀），因此滤镜再把它色相转回主题的蓝紫色域。
  `tools/audit-theme.mjs` 会专门检查这一对资产确实**不相同** —— 若哪天暗色模式
  误用了亮色那张，检查会直接报错。
* **纯白与纯黑互换。** 亮色渐变的终点是 `#ffffff`，暗色渐变的终点是 `#05060d`，
  形成对称的收尾。
* 副标题同理：hero 的缀饰文字、卡片阴影、分隔线、星点颜色在两套主题里逐一对齐。

### 默认主题

**暗色是站点默认**，与访问者的操作系统设置无关：访客从没点过切换按钮时，
一律以暗色打开。切换按钮固定在右上角，点过之后选择会记在 `localStorage`，
此后一直以该选择为准 —— 亮色只差一次点击。

判定顺序（全部在首屏渲染前完成，因此不会闪白/闪黑）：

| 优先级 | 依据 |
|---|---|
| 1 | `?theme=light` / `?theme=dark`，同时写入 `localStorage` |
| 2 | `localStorage["cust-astro-theme"]`（切换按钮写入） |
| 3 | 兜底：**暗色** |

想让站点重新跟随系统，或不希望 `?theme=` 留下记忆，改
`tools/build.mjs` 里的 `THEME_BOOT` 与 `assets/js/main.js` 顶部的
`forcedTheme` 处理即可。

## 无障碍

* 正文与背景的对比度全部满足 WCAG AA（正文 ≥ 4.5:1，大字号渐变文字 ≥ 3:1），
  并且是按**渐变上的每一个色标**逐个核算，而不是只测中值。
* 灯箱是真正的对话框：`aria-modal`、Esc 关闭、左右方向键切换、Tab 焦点锁定、支持触摸滑动。
* 键盘可以操作所有交互元素；有跳到主内容的 skip link；`prefers-reduced-motion`
  下关闭全部动画。

## 工具脚本（可选）

```bash
node tools/build.mjs         # 由 tools/pages/*.mjs + assets/icons.svg 生成五个 HTML
node tools/verify.mjs        # 校验链接、锚点、图片、图标引用是否都存在
node tools/audit-theme.mjs   # 审计亮暗令牌配对、色相走向与对比度
python tools/optimize_images.py   # 由 image/ 重新生成 assets/img/
```

`build.mjs` 只是为了让页头、页脚与图标集保持单一来源 —— 生成的 HTML 就是普通静态
文件，**删掉 `tools/` 整个目录网站依然照常运行**。直接编辑 `index.html` 等文件同样
有效，只是下次跑 `build.mjs` 会被覆盖。

## 调试用的 URL 参数

| 参数 | 作用 |
|---|---|
| `?theme=dark` / `?theme=light` | 强制指定主题并记住，方便分享与截图 |
| `?motion=off` | 关闭滚动揭示与星点闪烁，直接渲染终态 —— 截图、导出、自动化视觉检查用 |

例如：`gallery.html?theme=dark&motion=off`
